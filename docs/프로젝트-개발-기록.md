## 문제 해결 기록

---

### [구조 개선] 프론트엔드-백엔드 분리 → 단일 서버 통합

**문제 상황**

초기 구조에서는 프론트엔드(`new_fe/`)와 백엔드(`fragrance-be/`)가 분리되어 있어,
로컬 개발 시 서버를 두 개 실행해야 했다.

- 백엔드: `uvicorn main:app --reload` → `http://127.0.0.1:8000`
- 프론트엔드: 별도 정적 서버 (Live Server 등) → `http://127.0.0.1:5500`

배포 시에도 서버 두 개를 따로 관리해야 하는 구조였다.

**해결 과정**

1. `fragrance-be/static/` 디렉토리 생성 후 `new_fe/`의 정적 파일을 복사
2. `main.py`에 FastAPI `StaticFiles` 마운트 추가
3. `/`, `/pages/{name}.html` 라우트를 `FileResponse`로 처리
4. 프론트엔드 JS의 API base URL을 상대경로(`""`)로 변경

**핵심 코드 — `main.py`**

```python
from fastapi.responses import FileResponse
from fastapi.staticfiles import StaticFiles

STATIC_DIR = os.path.join(os.path.dirname(__file__), "static")

# ① API 라우터 먼저 등록
app.include_router(scent.router)
app.include_router(products.router)
app.include_router(naver.router, prefix="/naver")

@app.get("/")
def root():
    return FileResponse(os.path.join(STATIC_DIR, "index.html"))

@app.get("/pages/{page_name}.html")
def get_page(page_name: str):
    filepath = os.path.join(STATIC_DIR, "pages", f"{page_name}.html")
    if not os.path.exists(filepath):
        return FileResponse(os.path.join(STATIC_DIR, "index.html"), status_code=404)
    return FileResponse(filepath)

# ② StaticFiles는 API 라우터 등록 후 마지막에 마운트
app.mount("/js", StaticFiles(directory=os.path.join(STATIC_DIR, "js")), name="js")
app.mount("/styles", StaticFiles(directory=os.path.join(STATIC_DIR, "styles")), name="styles")
app.mount("/assets", StaticFiles(directory=os.path.join(STATIC_DIR, "assets")), name="assets")
```

**결과**

`uvicorn main:app --reload` 한 번만 실행하면
`http://127.0.0.1:8000` 에서 프론트엔드와 API 모두 서빙된다.

### [에러] StaticFiles 사용 시 `aiofiles` 미설치 오류

**에러 메시지**

```
RuntimeError: The `aiofiles` package is required to use `StaticFiles`.
Install it with: pip install aiofiles
```

**원인**

FastAPI(Starlette)의 `StaticFiles`는 비동기 파일 읽기를 위해 `aiofiles` 패키지가
별도로 필요한데, 기존 `requirements.txt`에 없었다.

**해결**

```powershell
python -m pip install aiofiles
pip freeze | Out-File -Encoding utf8 requirements.txt
```

`requirements.txt`에 `aiofiles==25.1.0`이 추가됐다.

---

### [에러] requirements.txt UTF-16 LE 인코딩 문제

**문제 상황**

Linux 배포 환경에서 `pip install -r requirements.txt` 실행 시 다음 오류 발생:

```
ERROR: Invalid requirement: '\xff\xfe'
```

**원인**

Windows PowerShell 5.1의 기본 파일 출력 인코딩이 **UTF-16 LE (BOM 포함)** 이다.
`pip freeze > requirements.txt` 또는 `>` 리다이렉션으로 생성하면 UTF-16 LE로 저장되어,
Linux의 pip가 읽지 못한다.

**해결**

```powershell
pip freeze | Out-File -Encoding utf8 requirements.txt
```

PowerShell에서 `-Encoding utf8`을 명시해 UTF-8로 저장.

> **앞으로 주의**: Windows에서 requirements.txt를 갱신할 때는 반드시
> `Out-File -Encoding utf8` 또는 `Set-Content -Encoding utf8`을 사용할 것.

### [에러] Windows에서 `pip` 직접 호출 실패

**문제 상황**

가상 환경 활성화 후 `pip install aiofiles` 실행 시 exit code 1 반환.

**원인**

Windows 환경에 따라 `pip` 또는 `pip.exe`가 PATH에 올바르게 등록되지 않거나
권한 문제가 발생할 수 있다.

**해결**

```powershell
python.exe -m pip install aiofiles
```

`python -m pip` 방식으로 호출하면 현재 활성화된 가상 환경의 pip를 확실히 사용한다.

### [구조 개선] API 라우트 순서와 StaticFiles 충돌

**문제 상황**

`StaticFiles`를 API 라우터보다 먼저 마운트하면 `/js`, `/styles` 등의 경로가
정적 파일 핸들러에 먼저 매칭되어 API 라우트와 충돌할 수 있다.

**해결**

FastAPI는 라우트를 등록 순서대로 매칭한다.
`app.include_router()` 와 `@app.get()` 으로 API 라우트를 먼저 등록하고,
`app.mount()`는 항상 파일 맨 끝에 위치시킨다.

**결과**

API 엔드포인트와 정적 파일 경로가 충돌 없이 동작한다.

### [개선] API base URL 하드코딩 → 상대경로로 변경

**문제 상황**

`shared.js`에서 API 호출 기본 URL이 `http://127.0.0.1:8000`으로 하드코딩되어 있어,
배포 환경에서 CORS 에러 또는 잘못된 호스트 요청이 발생할 수 있었다.

**해결**

```javascript
// 변경 전
const API_BASE_URL = "http://127.0.0.1:8000";

// 변경 후
const API_BASE_URL =
  window.SCENT_API_BASE_URL ||
  localStorage.getItem("SCENT_API_BASE_URL") ||
  "";   // 기본값: 동일 오리진 상대경로
```

**결과**

프론트엔드와 API가 같은 서버(포트)에서 서빙되므로 CORS 설정 없이 동작한다.
필요하면 `window.SCENT_API_BASE_URL` 또는 `localStorage`로 오버라이드 가능.

### [구조 개선] 네이버 쇼핑 검색 API 종료 → 수동 큐레이션 데이터로 전환 (2026-08)

**문제 상황**

로컬에서 `uvicorn main:app --reload`로 서버를 띄운 뒤 상품 검색을 테스트하던 중
`/naver/search`가 502 에러(`Naver API returned an error.`)를 반환했다.

`utils/naver_api.py`가 호출하는 `NAVER_CLIENT_ID`/`NAVER_CLIENT_SECRET`로
네이버 오픈API(`https://openapi.naver.com/v1/search/shop.json`)를 직접 호출해보니:

```json
{
  "errorMessage": "Invalid search api (존재하지 않는 검색 api 입니다.)",
  "errorCode": "SE05"
}
```

**원인**

네이버 공지 확인 결과, **쇼핑·책·전문자료 검색 API는 NAVER API HUB 이관 대상에서 제외되어
2026년 7월 31일부로 완전히 종료**되었고, 공식 대체 API가 제공되지 않는다. Client ID/Secret을
새로 발급받아도 해결되지 않는, 네이버 쪽에서 서비스 자체를 내린 문제였다.

**검토했으나 채택하지 않은 대안**

| 대안 | 기각 사유 |
|---|---|
| NAVER API HUB로 이관된 검색 API (웹문서/쇼핑인사이트/검색어트렌드) | 전부 "검색결과·통계"용 응답이라 상품명·이미지·가격·판매처 같은 구조화된 상품 데이터가 없음 |
| 쿠팡파트너스 API (`/product/search`) | 본질이 "내 콘텐츠에 쿠팡 배너·딥링크를 노출"하는 어필리에이트 프로그램. API 사용 자체가 15만원 매출 달성 후 "최종승인"을 받아야 가능해 이 프로젝트 용도(백엔드 상품 데이터 소스)와 맞지 않음. 승인 후에도 시간당 10회 호출 제한(문서상 50회/분과 다름) + 3회 위반 시 계정 영구정지 리스크 |
| 쿠팡 Open API (`developers.coupang.com`) | 사업자등록 + Wing 판매자 계정 필수. 내 상품을 등록·관리하는 셀러용 API지 전체 카탈로그 검색용이 아님 |
| 11번가 오픈API | 상품 검색 등 대부분 기능이 셀러 등록 필수, 일반회원은 상품/카테고리 조회만 가능 |
| 다나와 오픈API | 2019년에 서비스 전체 종료 (상품조회·검색 포함) — 이미 오래전에 죽은 API |
| 네이버쇼핑/쿠팡 직접 크롤링 | 네이버는 메인페이지 외 크롤링 기본 금지. 잡코리아 vs 사람인, 야놀자 vs 여기어때 등 국내 판례상 부정경쟁방지법(제2조 1호 파목)·정보통신망법 제48조 위반 소지가 있어 리스크 대비 실익이 낮다고 판단 |

**해결 과정**

이 서비스가 다루는 product × scent × fragrance 조합이 14개(샴푸/바디워시 × 과일향·플로럴향·우디향)로
**고정·제한된 집합**이라는 점에 착안해, 실시간 외부 검색 대신 **수동으로 큐레이션한 상품 데이터를
MongoDB에 저장해두고 그대로 서빙**하는 구조로 전환했다.

1. `database/mongodb.py`에 TTL 없는 `curated_products` 컬렉션 접근 함수 추가 (기존 `naver_cache`는 1시간 TTL이라 큐레이션 데이터 저장에 부적합)
2. `services/curated_product_service.py` 신규 작성 — `curated_products`에서 조회해 기존과 동일한 `PaginatedProductResponse` 형태로 반환 (기존 `product_service.py`와 함수 시그니처 동일하게 맞춰 교체 부담 최소화)
3. `api/products.py`의 의존성을 `product_service` → `curated_product_service`로 교체, 네이버 관련 예외 처리(`requests.Timeout` 등) 제거
4. `scripts/import_curated_products.py` 작성 — CSV(`scripts/curated_products_template.csv`)를 읽어 `curated_products`에 upsert (재실행 안전, `productId` 기준 덮어쓰기)
5. 네이버 API에 의존하는 기존 코드는 삭제하지 않고 **주석 처리로 비활성화**만 진행 (`main.py`의 `naver.router` 마운트, `services/product_service.py` 전체 — 향후 유효한 대체 API를 찾으면 재사용 가능하도록 구조 보존)

**결과**

- 외부 API 호출 없이 `/fragrances/{product}/products`, `/fragrances/{product}/{scent_slug}/products`가
  `curated_products` 컬렉션 데이터로 정상 동작 (임시 포트로 직접 기동해 200 응답 확인)
- `/naver/search`는 404 (라우터 미마운트로 의도적으로 비활성화)
- 남은 작업: `scripts/curated_products_template.csv`에 실제 상품 정보(상품명/이미지/가격/판매처/링크)를
  수동으로 채운 뒤 `python scripts/import_curated_products.py` 실행 → 가격은 주기적(월 1회 권장)으로
  사람이 직접 재확인해 갱신

## 계속 개발하기 위해 알아야 할 내용

### 정적 파일 수정 위치

`fragrance-be/static/` 이 정본이다. `new_fe/`는 레거시로 더 이상 사용하지 않는다.

### 공통 JS 헬퍼 추가 위치

`fragrance-be/static/js/shared.js` — `window.ScentApp` 네임스페이스에 추가.
페이지별 동작은 각 페이지 스크립트에만 작성한다.

### 새로운 향 데이터 추가

`scripts/seed_data.py`를 수정 후 재실행.
데이터 스키마는 `models/` 폴더의 Pydantic 모델 참고.

### 백엔드 로직 추가 위치

- 새 API 엔드포인트: `api/` 폴더에 라우터 파일 추가 → `main.py`에 `include_router`
- 비즈니스 로직: `services/`에 분리 (라우터는 얇게 유지)
- 외부 API 호출: `utils/`에 추가

### 환경 변수 추가 시

`.env`와 `.env.template` 둘 다 업데이트 (`.env.template`에는 실제 값 제외).

### CORS 설정

현재 `main.py`에 `https://scent-fe.vercel.app` 만 허용되어 있다.
다른 프론트엔드 도메인이 추가되면 `allow_origins` 리스트에 추가한다.
